# Система учёта оборудования — Этапы 1–6

Локальное веб-приложение для учёта оборудования отдела АСУТП. Без сервера БД,
без входа с паролем — просто запускаете и работаете в браузере. Для
развёртывания на постоянно работающем сервере компании — см. `DEPLOY.md`.

## Что уже реализовано (Этапы 1–6)

- Реестр оборудования: список, поиск (по инв./серийному номеру, наименованию, модели),
  фильтры по категории/статусу/местонахождению/ответственному, **экспорт в Excel**
  (кнопка на странице реестра, с учётом применённых фильтров)
- Карточка единицы оборудования со всеми полями
- Добавление нового оборудования (постановка на учёт)
- Передача оборудования другому сотруднику и/или перемещение в другое помещение,
  с автоматической фиксацией в неизменяемом журнале истории (виден на карточке)
- Изменение статуса оборудования (например, «отправить в ремонт» / «вернуть из ремонта») —
  тоже фиксируется в истории с автоматическим определением типа события
- Общий журнал истории (`/history/`) по всему оборудованию сразу, с фильтрами
  по типу события, оборудованию, сотруднику, местонахождению и диапазону дат
- Формирование документов в Word (.docx) через раздел «Документы»:
  - Акт приёма-передачи, акт внутреннего перемещения, акт возврата, акт списания —
    с выбором оборудования из реестра; состояние оборудования обновляется
    автоматически, событие пишется в историю со ссылкой на документ
  - Ведомость оборудования и инвентаризационная ведомость (весь реестр)
  - Список оборудования сотрудника / кабинета — кнопка на странице реестра
    при активном соответствующем фильтре
  - Карточка единицы имущества — скачивается сразу в Word с полной историей
    эксплуатации
  - Реестр всех сформированных документов (`/documents/`) с возможностью
    скачать файл повторно
- **Главная страница-дашборд** (`/reports/`) — сводка по количеству оборудования,
  разбивка по статусам и категориям, суммарная балансовая стоимость,
  последние события из истории
- **Отчёты по материально ответственным лицам** (`/reports/mol/`) — список МОЛ
  с количеством и стоимостью закреплённого оборудования, детальный отчёт по
  каждому со ссылкой на формирование печатного списка
- **Резервное копирование одной командой**: `python manage.py backup_db` —
  копирует базу в папку `backups/` с меткой времени, автоматически
  подчищает старые копии (см. `DEPLOY.md` про настройку по расписанию)
- Готовая админ-панель Django (`/admin/`) для управления справочниками:
  подразделения, кабинеты, сотрудники, категории, статусы, типы документов

## Как запустить

Нужен установленный Python 3.10+.

### 0. Если вы уже разворачивали более раннюю версию этого проекта

Список зависимостей (`requirements.txt`) со временем пополнялся (например,
`whitenoise`, `openpyxl`). Если после обновления файлов видите ошибку вида
`ModuleNotFoundError: No module named 'whitenoise'` — просто переустановите
зависимости в уже существующем виртуальном окружении:

```bash
venv\Scripts\Activate.ps1        # Windows, или source venv/bin/activate на Linux/macOS
pip install -r requirements.txt
```

### 1. Первый запуск

```bash
# Распакуйте архив и перейдите в папку проекта
cd equipment_system

# Создайте виртуальное окружение
python3 -m venv venv

# Активируйте его
# Linux/macOS:
source venv/bin/activate
# Windows (PowerShell):
venv\Scripts\Activate.ps1

# Установите зависимости
pip install -r requirements.txt

# База данных SQLite уже создана и включена в архив (db.sqlite3) —
# отдельно накатывать миграции не нужно. Если захотите начать с чистой базы:
#   rm db.sqlite3
#   python manage.py migrate

# Создайте администратора для доступа к /admin/ (задаётся один раз)
python manage.py createsuperuser
```

### 2. Обычный запуск (каждый раз)

```bash
source venv/bin/activate      # активировать окружение
python manage.py runserver    # запустить сервер
```

Откройте в браузере: **http://127.0.0.1:8000**

Чтобы остановить сервер — `Ctrl+C` в терминале.

### 3. Как пользоваться

1. Сначала зайдите в **админку** (`/admin/`, нужен логин, который вы создали
   через `createsuperuser`) и заполните справочники: подразделения, кабинеты,
   сотрудников, категории и статусы оборудования.
2. После этого на главной странице (`/equipment/`) добавляйте оборудование
   через кнопку «+ Добавить оборудование». Отметьте флаг «Материально
   ответственное лицо» у нужных сотрудников в админке — они появятся в
   отчётах по МОЛ.
3. На карточке оборудования кнопка «Передать / переместить» фиксирует
   передачу другому сотруднику или смену кабинета — событие сразу
   появляется в истории на этой же странице.
4. Раздел «Документы» (`/documents/`) — формирование печатных Word-документов:
   - «+ Сформировать акт» → выберите тип (приёма-передачи / перемещения /
     возврата / списания) → отметьте оборудование чекбоксами → заполните
     поля → документ сформируется и состояние оборудования обновится
     автоматически (со ссылкой на документ в истории)
   - Ведомость оборудования / инвентаризационная ведомость — доступны
     прямо из меню «+ Сформировать акт»
   - Список сотрудника/кабинета — кнопка появляется на странице реестра,
     если применить фильтр по сотруднику или местонахождению
   - Карточка единицы имущества — кнопка «Скачать карточку (Word)» на
     странице самого оборудования
5. Главная страница (`/reports/`) — дашборд со сводными показателями и
   последними событиями. Раздел «Отчёты по МОЛ» (`/reports/mol/`) —
   список материально ответственных лиц с количеством и стоимостью
   закреплённого за ними оборудования.
6. Кнопка «Экспорт в Excel» на странице реестра — выгружает текущий
   отфильтрованный список в `.xlsx`.

> Примечание: сама система учёта (`/equipment/...`, `/documents/...`) открывается
> без пароля. Пароль запрашивается только при заходе в `/admin/` — это стандартная
> защита панели администратора Django, отключать её не рекомендуется,
> так как через неё можно удалять данные.

## Резервное копирование

Самый простой способ — скопировать файл `db.sqlite3` в другое место
(вручную, раз в день). Также в проекте есть готовая команда:

```bash
python manage.py backup_db
```

Она сама копирует базу в папку `backups/` с меткой даты и времени и
подчищает копии старше 30 последних (`--keep N`, чтобы изменить). Как
поставить её на автоматическое расписание — см. `DEPLOY.md`.

Сгенерированные
Word-документы дополнительно хранятся в папке `media/documents/` — если
важно сохранять историю выданных актов, бэкапьте и её вместе с базой.

## Структура проекта

```
equipment_system/       # настройки проекта Django
employees/               # сотрудники, подразделения, кабинеты
equipment/                # реестр оборудования, справочники категорий/статусов
history/                  # неизменяемый журнал перемещений
documents/                # типы документов, формирование актов/ведомостей,
                           # .docx-шаблоны (documents/doc_templates/),
                           # единый генератор (documents/services/generator.py)
reports/                  # дашборд, отчёты по МОЛ, экспорт в Excel,
                           # команда резервного копирования (backup_db)
media/documents/          # сгенерированные Word-файлы (создаётся автоматически)
backups/                   # резервные копии базы (создаётся командой backup_db)
manage.py
requirements.txt
DEPLOY.md                  # как развернуть на постоянно работающем сервере
Dockerfile                  # описание Docker-образа
docker-compose.yml           # запуск системы в Docker одной командой
docker/entrypoint.sh          # что выполняется при старте контейнера
db.sqlite3                 # база данных (один файл)
```

Если понадобится изменить оформление документов (шапку, расположение полей) —
правьте `documents/build_templates.py` и запустите его заново
(`python documents/build_templates.py`), либо откройте нужный `.docx` из
`documents/doc_templates/` прямо в Word и подправьте текст вокруг `{{ }}`
вручную (сами плейсхолдеры и строки-маркеры `{%tr for/endfor%}` трогать нельзя).

## Дальнейшие шаги (по плану разработки)

Все 6 этапов из первоначального плана реализованы. Возможные дальнейшие
доработки (по желанию): вход с паролем для всех пользователей (не только
`/admin/`), уведомления о просроченных ремонтах, штрихкоды/QR на карточках
оборудования для быстрого поиска.

## Развёртывание на сервере

Если систему нужно не просто запускать локально, а держать постоянно
доступной по сети компании — подробная инструкция в файле `DEPLOY.md`:
самый простой способ — через **Docker** (`docker compose up -d --build`,
всё уже настроено — `Dockerfile` и `docker-compose.yml` в комплекте), а
также классические варианты без Docker для Linux (gunicorn + systemd + Nginx)
и Windows (waitress + служба через NSSM).
